Design: dstl sparse alltoall

Sparse personalized all-to-all: every rank sends messages to a (small, dynamic) set of destinations, and no rank knows in advance from whom it will receive. Implements the four protocols of Hoefler, Siebert, Lumsdaine, Scalable Communication Protocols for Dynamic Sparse Data Exchange (PPoPP 2010), selected by a tag. Unlike MPI_Alltoallv, NBX has communication complexity linear in the number of messages actually sent, not in the communicator size.

Primitives

Primitive Status
probe_result, v2::mprobe, v2::improbe done (#83)
v2::mrecv, v2::imrecv (take probe_result by value, size deferred buffers via infer(comm_op::mrecv, ...)) done (#85)
ibarrier (v2 returns a request) done (#84)
request_vector, testall done (#82)
reduce_scatter_block missing — needed for PCX
one-sided windows (MPI_Win, MPI_Accumulate) missing — needed for RSX

Algorithm selection

Tags in the style of the existing execution_policy::* / layout::* tags (tags.hpp):

cpp namespace dstl::sparse_alltoall_algorithm { struct nbx {}; // nonblocking consensus: issend + improbe + ibarrier struct pex {}; // personalized exchange: alltoall of counts struct pcx {}; // personalized census: reduce_scatter of message flags struct rsx {}; // remote summing: MPI_Accumulate into a counter window } template <typename T> concept is_sparse_alltoall_algorithm = /* one of the tags above */;

The tag is the first argument (like std::execution policies). Every entry point has an overload without it that defaults to nbx.

Layer 1 — callback primitive

cpp template < is_sparse_alltoall_algorithm Algorithm, sparse_send_buffer Sends, std::invocable<incoming_message>p OnMessage, mpi::experimental::convertible_to_mpi_handle<MPI_Comm> Comm = MPI_Comm> void dstl::sparse_alltoall(Algorithm, Sends&& sends, OnMessage&& on_message, Comm const& comm = MPI_COMM_WORLD);

Input: sparse_send_buffer

A range of (dest, inner_range) pairs — the existing sparse_nested_send_buffer (payload.hpp), plus the requirement that each inner range is contiguous_range && sized_range, since inner ranges are sent directly without copying. Inner ranges are plain ranges (std::vector<T>, std::span<T>, …); they need not be send_buffers, so payload types without a builtin MPI type work (their type comes from the value-type channel below).

Datatype: the value-type channel

The payload datatype is attached once to the whole structure, not per message:

cpp dstl::sparse_alltoall(sends | kamping::v2::views::with_value_pool(p), on_message, comm); dstl::sparse_alltoall(sends | kamping::v2::views::with_value_type(dt), on_message, comm); dstl::sparse_alltoall(sends, on_message, comm); // builtin payload: value_type() fallback

The implementation reads kamping::v2::value_type(sends) once (as request_reply does) and uses it for every send. Consequences:

  • One datatype per call, by construction.
  • The datatype must outlive the call; with with_value_pool the type_pool guarantees this.
  • No per-message views are created just to carry a type.

Callback: incoming_message

The protocols know different things about an incoming message: PEX knows source and size up front, NBX/PCX only learn about a message by probing it. If the callback always received a probe_result, PEX would have to probe every message anyway and lose part of its advantage. So the callback receives an algorithm-independent handle (name tentative):

cpp class incoming_message { public: int source() const; template <typename T> std::optional<int> count() const; // elements of T, nullopt for MPI_UNDEFINED auto recv(RBuf&& rbuf) &&; // blocking; goes through infer() auto irecv(RBuf&& rbuf) &&; // -> iresult<RBuf> auto irecv(Request&& request, RBuf&& rbuf) &&; // caller-supplied request };

  • NBX / PCX: wraps a probe_result; recv / irecv are v2::mrecv / v2::imrecv.
  • PEX: holds (source, count); recv / irecv are a targeted recv / irecv, sizing deferred buffers from the known count.

recv / irecv size deferred buffers (views::resize, …) from the count, computed with the receive buffer’s datatype — so only the sizes of sent and received elements have to match, not the declared types.

Contract: move-only, received exactly once; dropping an unreceived message terminates, like mpi::experimental::message (for NBX / PCX this falls out of probe_result; the PEX handle needs its own flag). The callback may move the handle out and receive it later, as long as that happens before sparse_alltoall returns.

Open: PEX exchanges counts in units of the send datatype. Either convert to the receive buffer’s datatype via the type sizes, or require the sizes to match.

Shared send phase

All four protocols start by sending every (dest, inner) pair. This lives in one place, parameterized by the send mode:

  • NBX uses issend (see below); PEX, PCX and RSX use isend.
  • Requests go into a request_vector; inner ranges are sent as (data, size, value_type).

  • Owning per-message views (e.g. views::serialize applied via std::views::transform) would be destroyed while their send is in flight. For non-borrowed_range inner types, the send phase moves each one into an internal vector that lives until all sends complete; for borrowed inner types this is compiled away. Not implemented yet — until then, materialize first:

    cpp auto staged = sends | std::views::transform([](auto& msg) { auto& [dst, data] = msg; return std::pair{dst, data | kamping::views::serialize}; }) | std::ranges::to<std::vector>(); dstl::sparse_alltoall(staged, callback, comm);

Protocols

NBX

1. issend every message (synchronous mode!), collecting requests 2. loop: if (auto probe = improbe(MPI_ANY_SOURCE, tag, comm)) on_message(incoming_message{std::move(*probe)}) if (!barrier_started && testall(send_requests)) barrier = ibarrier(comm); barrier_started = true if (barrier_started && barrier.test()) break

The sends must be synchronous (issend): termination relies on a completed send meaning the receiver has matched the message, which is what allows a rank to enter the ibarrier once all its sends are complete. With isend, a small message can complete locally before it is matched, and the protocol can terminate with messages still in flight.

PEX

alltoall of per-destination counts (O(p) per rank), then post the receives for every non-zero count and send. Sizes are known up front, so no probing; delivery order is predictable.

PCX

reduce_scatter_block of a 0/1 “I send to you” vector yields the number of incoming messages; then mprobe(MPI_ANY_SOURCE, tag) that many times. Needs a reduce_scatter_block wrapper (small, follows the existing collectives pattern).

RSX

Each sender MPI_Accumulates +1 into a counter on each destination within a fence epoch, yielding the number of incoming messages; then probe as in PCX. Needs one-sided windows, which mpi-core does not have yet — either a minimal window wrapper or raw MPI inside dstl.

Message isolation across calls

All protocols send on a reserved tag. After its barrier completes, a fast rank can start the next sparse_alltoall and send while a slower rank is still probing in the previous one and may match the new message. Open: pick one mechanism for all protocols:

  • a final barrier() (as in the original sketch) — simple, costs a collective per call;
  • a duplicated communicator per call (or cached per communicator);
  • tags alternating between consecutive calls.

Layer 2 — flat buffer convenience

Built on Layer 1. Takes a variadic send buffer (flat data + per-rank counts + displacements) and only sends to ranks with non-zero counts. Its input is already flat, so plain with_type applies.

cpp template < is_sparse_alltoall_algorithm Algorithm, mpi::experimental::data_buffer_v SBuf, mpi::experimental::recv_buffer RBuf, is_output_layout Layout = layout::unordered, mpi::experimental::convertible_to_mpi_handle<MPI_Comm> Comm = MPI_Comm> void dstl::sparse_alltoall(Algorithm, SBuf&& sbuf, RBuf&& rbuf, Layout = {}, Comm const& comm = MPI_COMM_WORLD);

NBX / PCX / RSX deliver in arrival order. The output order reuses the existing layout tags: layout::unordered (default) appends in arrival order; layout::ordered_by_source yields the MPI_Alltoallv layout (grouped by increasing source rank).

Higher-level convenience variants (built on Layer 1)

```cpp // Collect all received messages as (source, data) pairs template auto sparse_alltoall(Sends&&, Comm const&) -> std::vector<std::pair<int, std::vector>>;

// Flat: all elements concatenated + per-element source annotation template auto sparse_alltoall(Sends&&, Comm const&) -> std::pair<std::vector, std::vector>; ```

Both are thin wrappers over the callback primitive, and accept the algorithm tag like it.

Dropped: transform_messages

The original design had sends | dstl::views::transform_messages(adaptor) to apply a view to every message, mainly to attach a datatype per message (with_auto_pool(p), with_type(dt)). The value-type channel (with_value_type / with_value_pool, see value_type.md) replaces that with a single whole-buffer annotation. Remaining per-message transformations that change the data (e.g. views::serialize) are written with std::views::transform on the pairs — transform_messages was only shorthand for it. The owning-view lifetime issue is independent of the spelling and handled in the shared send phase.

Implementation order

  1. Shared send phase + incoming_message + NBX (all primitives available).
  2. PEX (needs only alltoall).
  3. PCX, after a reduce_scatter_block wrapper.
  4. RSX, after a minimal window wrapper (or raw MPI inside dstl).
  5. Layer 2 and the convenience variants.
